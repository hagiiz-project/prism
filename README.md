# プリズム

科学を伝えるための道具・人・場所を集めたカタログ。**CSVを直せば、公開されているサイトが自動で更新されます。**

---

## GitHubのWeb画面だけで運用する手順

### 手順1　リポジトリを作る

1. https://github.com/new を開く
2. Repository name に `prism`
3. **Public** を選ぶ（Privateだと無料プランでGitHub Pagesが使えません）
4. 「Add a README file」は**チェックを外す**（これから上げるファイルと衝突します）
5. Create repository

### 手順2　ファイルを上げる

作成直後の画面にある **「uploading an existing file」** をクリック。
このフォルダ（`prism-repo`）の**中身をすべて**ドラッグ&ドロップします。

> ドラッグするのは `prism-repo` フォルダそのものではなく、**中にあるファイルとフォルダ**です。
> `.github` フォルダも必ず含めてください（隠しフォルダ扱いで見落としやすい）。
> Macで `.github` が見えないときは、Finderで `Command + Shift + .` を押すと表示されます。

下の「Commit changes」を押して確定します。

### 手順3　GitHub Pages を有効にする

1. リポジトリの **Settings** タブ
2. 左メニューの **Pages**
3. Source を **GitHub Actions** に変更（"Deploy from a branch" ではありません）

### 手順4　最初のビルドを走らせる

1. **Actions** タブを開く
2. 左の "build and deploy" をクリック
3. 右の **Run workflow** ボタン → 緑の Run workflow

2〜3分で緑のチェックが付きます。**Settings → Pages** に戻ると、
`https://<あなたのユーザー名>.github.io/prism/` が表示されます。これが公開URLです。

### 手順5　アフィリエイトIDを入れる（収益化するとき）

1. **Settings → Secrets and variables → Actions**
2. **New repository secret** を押して、下記を1つずつ登録

| Name | Secret に入れる値 |
|---|---|
| `AMAZON_TAG` | AmazonアソシエイトのトラッキングID（例 `yourname-22`） |
| `RAKUTEN_ID` | 楽天アフィリエイトID |
| `RAKUTEN_TRAVEL_ID` | 楽天トラベルのアフィリエイトID |
| `JALAN_ID` | じゃらんのvos値（使う場合） |

登録したら Actions → Run workflow をもう一度押すと、リンクに反映されます。

> **申請の順序に注意。** Amazonアソシエイトは審査時にサイトが公開済みで中身があることを求めます。
> **先に手順4まで終えて公開 → 申請 → IDを登録して再実行**、の順です。

## 毎日の運用（これだけ）

### 掲載を1件足す

1. `data/listings.csv` を開く
2. 右上の **鉛筆アイコン（Edit this file）**
3. 一番下に1行足す
4. 下の **Commit changes** を押す

→ Actionsが自動で走り、物品分解とビルドが実行され、**数分後には公開サイトに反映されます。**

CSVが読みにくければ、GitHubの表示を **Raw** から切り替えると表形式で見られます。

### 列の意味

`data/listings.csv` の主な列。空でよい列も多いです。

| 列 | 必須 | 内容 |
|---|---|---|
| `url` | ● | 一次情報のURL |
| `title` | ● | 名称 |
| `provider` | ● | 提供者名 |
| `providerType` | | 大学・研究機関 / 企業・メーカー / 科学館・博物館 / 自治体・公的機関 / NPO・市民団体 / 学会・専門団体 / クリエイター・YouTuber / 個人コミュニケーター / 研究者・専門家 |
| `media_type` | | youtube / tiktok / instagram / note / toy / kit / museum / event / person など24種 |
| `format` | | 表示用の形式名 |
| `act_group` | | みる・きく / つかう / よむ / やってみる / よぶ・あう / いく。**空なら自動で決まります** |
| `field` | | 分野。**またぐものは空でよい**（空だと虹色のカードになります） |
| `audience` `purpose` `topics` | | `|` 区切り |
| `txn` | | 無料 / 購入（買い切り）/ 予約（日時指定）/ 要見積もり / サブスク / フリーミアム |
| `更新頻度` | | 日次 / 週次 / 月次 / 年次。**週次以上が「今週の更新」に出ます** |
| `region_pref` `region_city` | | 「いく」で必須。**空だと旅行リンクが出ません** |
| `description` | ● | 1〜3文。**ここから物品が分解されます** |

`description` が薄いと物品分解も薄くなります。ここだけは丁寧に書いてください。

### 手元にPythonがなくても確認できる

Actionsのログに毎回こう出ます。

```
146件 → 物品 894点（毎回いるもの 584点 = 65%）
  安全確認で購入導線を止めるもの 24点／「いく」掲載 22件
■ 何をしたいか
   よむ  10件   ← 手薄
```

「← 手薄」が出た区分に掲載を足していけば、網羅が埋まります。

## ファイル構成

```
├─ data/listings.csv          ← 触るのはここだけ
├─ prism/                     パイプライン
│   ├─ taxonomy.py            語彙（メディア24種・動詞6種）
│   ├─ schema.py              CSVの列定義
│   ├─ extract.py             URL→掲載レコード、監視フィードの自動推定
│   ├─ decompose.py           物品分解（掲載でも送客でも通る共有ステージ）
│   ├─ monetize.py            アフィリエイト解決・開示文・安全ゲート
│   └─ discover.py            探索元20経路
├─ run.py                     CLI（decompose / coverage / submit / seeds）
├─ site/
│   ├─ template.html          画面。__PRISM_DATA__ にデータが差し込まれる
│   └─ build.py               CSV → 1枚のHTML
└─ .github/workflows/deploy.yml   push・毎朝5時・手動でビルドして公開
```

生成物（`_site/`、`data/materials.csv`）はコミットしません。Actionsが毎回作り直します。

## 公開前に必ずやること

**フッターの連絡先を書き換える。** `site/template.html` の `REPLACE_WITH_YOUR_EMAIL` を実際のアドレスにしてください。掲載146件は実在の団体です。削除・修正の依頼窓口がないまま公開するのは避けてください。

**安全に関わる24点。** 保護めがね、ヘルメット、解剖ばさみ、火気。確認がすむまで購入リンクが出ない実装ですが、裏を返すと確認しないかぎり収益になりません。`prism/decompose.py` の物品マスタで `saf=` が付いているものです。

**開示文を消さない。** 準備物の下に1行あります。Amazon・楽天の規約要件であり、日本のステマ規制の対象でもあります。消すと収益源ごと失います。

## いまできていないこと

読み取り（見る・探す・絞る・並べ替える）は完全に動きます。**書き込みはできません。**

| 項目 | 状態 |
|---|---|
| リアクションの保存 | 押せるが再読み込みで戻る |
| 実施記録の投稿 | 表示枠のみ。投稿できない |
| 掲載フォーム | 説明のみ。投稿できない |
| 依頼フロー（要見積もり29件） | 未着手 |
| 商品画像 | ファビコンのみ |

静的サイトの限界です。ここから先はサーバー側（Supabase や Cloudflare D1）が必要になります。テーブルは `reactions` / `practices` / `submissions` の3つから始められます。

## 運用の全体像（スプレッドシート版）

サーバーは立てません。GoogleとGitHubだけで一周します。

```
  掲載フォーム（Googleフォーム）─┐
  自分で調査して手入力 ─────┴→ スプレッドシート（listings シート）
                                        │
                        毎朝5時＋pushのたび（GitHub Actions）
                                        ↓
                        run.py sync（取り込み・検査）
                                        ↓
                        run.py decompose（物品分解）
                                        ↓
                        site/build.py（1枚のHTML）
                                        ↓
                        GitHub Pages に公開
                                        │
  AIに聞く ── Apps Script（キーを保管）──┘ 同じシートを読む
```

### 手順A　スプレッドシートを用意する

1. 新しいスプレッドシートを作り、シート名を **`listings`** にする
2. `templates/spreadsheet_listings.csv` を **ファイル → インポート → 現在のシートを置換** で読み込む
   （1行目が列名、2行目が記入例。例の行は消して構いません）
3. `data/listings.csv` の中身を貼り付ければ、いまの146件がそのまま入ります
4. URLの `/d/` と `/edit` のあいだの文字列が **シートID** です。控えておきます
5. **ファイル → 共有 → ウェブに公開** → `listings` シートを **カンマ区切り(.csv)** で公開

> 「ウェブに公開」をしないと GitHub から読めません。共有リンクの設定とは別物です。

6. GitHubの **Settings → Secrets and variables → Actions** に `SHEET_ID` を登録

これ以降、**スプレッドシートを直せば翌朝には公開サイトが変わります。** すぐ反映したいときは Actions → Run workflow。

### 手順B　掲載フォームを作る

1. スプレッドシートの **ツール → 新しいフォームを作成**
2. 質問を、少なくとも `url` `title` `provider` `description` の4つ作る（この4つが空の行は公開されません）
3. 回答シートの列名を、`listings` と同じ名前に揃える

フォームの回答は別シートに入るので、`listings` シートに転記するか、回答シート名を `listings` にしてください。

### 取り込み時の検査

`run.py sync` は次の行を**公開しません**。Actionsのログに理由が出ます。

- 必須列（url / title / provider / description）が空
- URLが `http` で始まっていない
- URLが他の行と重複
- `status` が `gone` / `rejected` / `draft`

誤って壊れた行を上げても、サイトは壊れません。

## AIに聞く を有効にする

Gemini の APIキーを **サイトに置いてはいけません。** ブラウザの開発者ツールで誰でも見えます。
Apps Script を中継役にして、キーをそこに保管します。

1. スプレッドシートを開く → **拡張機能 → Apps Script**
2. `gas/Code.gs` の中身をすべて貼り付ける
3. 左の歯車（プロジェクトの設定）→ **スクリプト プロパティ** に登録

   | プロパティ | 値 |
   |---|---|
   | `GEMINI_API_KEY` | Google AI Studio で発行したキー |
   | `SHEET_ID` | スプレッドシートのID |
   | `SHEET_NAME` | `listings` |

4. 右上 **デプロイ → 新しいデプロイ → ウェブアプリ**
   - 次のユーザーとして実行： **自分**
   - アクセスできるユーザー： **全員**
5. 発行された `/exec` で終わるURLを、GitHubの Secrets に **`AI_ENDPOINT`** として登録
6. Actions → Run workflow

### なぜベクトル検索を使わないか

掲載が数百件のうちは、**全件をそのまま Gemini Flash に渡すほうが正確で、安くて、速い**からです。
埋め込みもベクトルDBも要りません。必要になるのは数千件を超えてからで、いま作ると複雑さだけが残ります。

### AIには id しか答えさせない

AIが返すのは「該当する掲載の id」と短い理由だけです。**価格・URL・連絡先はAIに書かせません。**
画面はサイトが持っている本物のデータからカードを描きます。AIに文章で説明させると、存在しない価格や
連絡先を作るためです。

## AIが動かないときの切り分け

「Actionsは緑なのにAIが使えない」場合、原因は次の4つのどれかです。**上から順に確認してください。**

### 1　サイト側に接続先が届いているか

公開サイトの「AIに聞く」に質問を入れて送信し、**何が表示されるか**を見ます。

| 表示 | 原因 | 対処 |
|---|---|---|
| 接続先が設定されていません | `AI_ENDPOINT` が空のままビルドされた | Secrets を確認し、Actions を再実行 |
| 想定外の応答を返しました | URLが `/dev` になっている／アクセス権が「全員」でない | デプロイ設定を直す |
| AI側のエラー：… | Apps Script まで届いている。**メッセージが原因そのもの** | 下の3へ |
| 何も起きない | ブラウザが古いHTMLを表示している | Ctrl+Shift+R（Macは Cmd+Shift+R）で再読み込み |

Actionsのログで「サイトを組み立てる」の中に
`※ AI_ENDPOINT が未設定のため…` と出ていたら、Secretの登録前にビルドされています。

### 2　接続先URLを直接開いてみる

`AI_ENDPOINT` に登録したURLをブラウザに貼って開きます。

- `{"ok":true,"items":146,...}` → Apps Script は正常。**1か4が原因**
- ログイン画面が出る → URLが `/dev` になっている。**`/exec` を使う**
- エラー画面 → **3へ**

### 3　Apps Script 側で自己診断を走らせる

`gas/Code.gs`（v2）に `selfTest` を入れてあります。
Apps Scriptエディタの上部、関数名の欄で **`selfTest`** を選び「実行」を押すと、下の実行ログに出ます。

```
1. SHEET_ID       : あり
2. SHEET_NAME     : listings
3. GEMINI_API_KEY : あり
4. 目録の件数     : 146 件
5. Geminiの応答   : {"ids":[45,12],"answer":"…"}
```

★が付いた行が原因です。よくある内容：

- `Gemini APIが 400 を返しました：API key not valid` → キーの貼り間違い
- `Gemini APIが 404 を返しました` → モデル名。`const MODEL` を `gemini-flash-latest` などに変える
- `シート「listings」が見つかりません` → シート名が違う（存在するシート名がログに出ます）
- `title と url の両方が入った行がありません` → 列名がシートと一致していない

### 4　コードを直したのに変わらない（最も多い）

Apps Script は、**貼り付けただけでは公開中のURLに反映されません。**

「デプロイ」→ **「デプロイを管理」** → 鉛筆マーク → バージョンを **「新バージョン」** → デプロイ。

「新しいデプロイ」を選ぶと**URLが変わってしまう**ので、必ず「デプロイを管理」から更新してください。
URLが変わった場合は、GitHubの `AI_ENDPOINT` も登録し直しが必要です。

## 意見・感想（みんなの声）

ホームに「みんなの声」を置いています。表示と投稿の両方が、AIと同じ Apps Script のURLを使います。
**新しく用意するものはありません。**

### 仕組み

```
サイトのフォーム → Apps Script → スプレッドシートの feedback シート（status=pending）
                                          ↓ あなたが published に変える
サイトの「みんなの声」 ← Apps Script ← feedback シート（published の行だけ）
```

`feedback` シートは**初回の投稿時に自動で作られます**。手で作る必要はありません。

### 列

| 列 | 内容 |
|---|---|
| `created_at` | 投稿日時（自動） |
| `name` | お名前。空なら「匿名」と表示 |
| `role` | 教員・学校関係／保護者／研究者・専門家／科学館・団体／企業／学生／その他 |
| `message` | 本文 |
| `page` | どの画面から送られたか |
| `status` | **`pending`（既定）／`published`／`rejected`** |
| `reply` | ここに書くと、その意見の下に「運営から」として表示されます |
| `admin_note` | 自分用のメモ。サイトには出ません |

### 運用

1. 投稿はすべて `pending` で入ります。**そのままではサイトに出ません**
2. シートを見て、出してよいものの `status` を `published` に変えます
3. 返答したいものは `reply` に書きます
4. 出したくないものは `rejected` にします（消さずに残せば、ニーズの集計に使えます）

Apps Script で **`fbStatus`** を実行すると、掲載待ちが何件あるかを実行ログで確認できます。

### なぜ既定で非公開にするか

投稿URLは誰でも叩けます。公開のまま運用すると、宣伝の書き込みが必ず入ります。
加えて、目的が「スプレッドシートでニーズをまとめる」ことなので、
**全部シートに溜め、出すものだけ選ぶ**構造のほうが目的に合います。

簡易な歯止めとして、本文にURLを含む投稿は受け付けず、5文字未満も弾き、
1日200件で受付を止めます。連絡先は集めていません（公開書き込み可能な場所に
メールアドレスを溜めるのは避けるべきなので、意図的にそうしています）。

### 反映の手順

- `gas/Code.gs` を貼り直す →「デプロイを管理」→ 鉛筆 → **新バージョン** → デプロイ
- `site/template.html` を GitHub に上げ直す → Actions を実行

この2つだけです。Secrets の追加はありません。

## 毎週の更新取得

週1回、掲載元をまとめて見に行き、新しく出た回を集めます。**判定と取得を同じ処理でやる**ので、
掲載フォームから入った新しい行も、次の週には自動で取得対象になります。設定作業は増えません。

```
毎週日曜 5時（Apps Script のトリガー）
  ① 判定  feed_type が空の行を調べ、フィードの有無を埋める
  ② 取得  auto_update=TRUE の行を見に行き、新しい回を stream シートに足す
  ③ listings の last_item_at を更新し、AIの目録も作り直す

毎朝 5時（GitHub Actions）
  listings と stream を読んで、サイトを組み立て直す
```

### 設置

Apps Script の左の**時計アイコン（トリガー）**→ トリガーを追加

- 実行する関数： `weeklyUpdate`
- イベントのソース： 時間主導型
- タイマー： 週タイマー（日曜・午前5〜6時など）

**初回は手で `weeklyUpdate` を実行してください。**146件の判定に数分かかります。
6分を超えそうになると自動で中断し、続きは次回に回します（`overTime_`）。

### listings に増える列（自動で追加されます）

| 列 | 誰が書くか |
|---|---|
| `feed_url` `feed_type` `auto_update` | 判定処理が埋める。あとから人が直してもよい |
| `last_item_at` | **観測された事実。**最後に新しい回が出た日 |
| `last_checked_at` `check_status` `fail_count` | 取得処理が書く |

`更新頻度` 列はそのまま残します。**あちらは提供者の申告、`last_item_at` は観測です。**
「週次」と書いてあるのに半年更新がないチャンネルは、その事実が見えるべきなので、混ぜません。

### stream シート（自動で作られます）

`listing_id` / `external_id` / `title` / `url` / `published_at` / `kind` / `fetched_at` / `status`

`status` を `hidden` にすると、その回だけサイトに出なくなります。

### 表示の決まり

- 直近7日の回を新しい順。**7日で0件なら直近30日に広げます**
- **1掲載につき最大2件。**毎日投稿するチャンネルに帯を占領させないため
- 全体で最大20件
- リンク先は掲載ページではなく**その回のURL**
- 回が1件も無いあいだは、これまでどおりチャンネル一覧を表示します

カードのバッジも変わります。「毎週更新」（申告）ではなく **「8月25日に更新」**（観測）。
まだ観測がない掲載は「毎週更新（申告）」と表示され、申告であることが分かります。

### 取得しないもの

TikTok・Instagram・X は公開フィードがないため、`auto_update` が自動で `FALSE` になります。
**掲載そのものは続きます。**検索にもカタログにも出ます。出ないのは「今週の更新」だけです。

### 失敗したとき

- 3回連続で失敗 → `check_status = fail`（表示は続ける）
- 4回連続 → `retired`（取得を止める。**カタログからは消しません**）

科学館の改装やチャンネル名の変更は、消えたのではなく変わっただけのことが多いためです。
Apps Script で **`updateStatus`** を実行すると、未判定・自動取得・自動不可・失敗・退役の件数が出ます。
